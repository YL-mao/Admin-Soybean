# 认证与会话安全：待办清单

> 范围：Soybean 管理端 + Sa-Token 严格 Header 模式。
> 更新：2026-09-03

## 已落地

- [x] `timeout` = 1 天（86400s）
- [x] `active-timeout` = 2 小时闲置冻结（7200s），`auto-renew` 开启
- [x] 关闭 Sa-Token Cookie 读/写（`is-read-cookie` / `is-lasting-cookie` = false），仅请求头 `saToken`
- [x] 移除 `getSession` 及 Cookie 会话恢复逻辑
- [x] 登录账密通过后先 `logout` 再建会话（换新 token）
- [x] 「记住我」只本地记账号，不记密码；与 token 存活无关
- [x] Cookie 兜底属性：`httpOnly` + `sameSite=Lax`；生产 `secure=true`
- [x] 业务异常 / Sa-Token 内部异常不对前端暴露技术堆栈（系统繁忙文案）
- [x] 删除 Layui/Thymeleaf 页面入口与相关依赖（统一 JSON API）

## 挂起待办

### 1. Token 前端存放位置

- [ ] 已定方向：`localStorage`；登录指纹（IP / UA / `X-Device-Id`）待落地
- [ ] 原则：XSS 下 JS 可读存储仍可偷 token；指纹用于防换环境复用

### 2. 高危操作二次认证（Sa-Token `openSafe`）

- [ ] 改密、删用户、授权、导出等高危接口增加 `openSafe` / `@SaCheckSafe`
- [ ] 二次认证通过后再开短时安全窗，过期需重新验密

### 3. XSS 加固（框架外）

- [ ] 审查前端危险输出（如 `v-html`）、富文本消毒
- [ ] 评估 CSP（Content-Security-Policy）

### 4. CSRF 加固（可选增强）

- [ ] 当前主要依赖：自定义头 `saToken` + 不读会话 Cookie
- [ ] 可选：写操作 Origin/Referer 校验，或 CSRF Token

### 5. 薄版 `getUserInfo`（业务对接阶段再做）

- [ ] 本地有 token 时，带 Header 校验 Redis 会话是否仍有效并刷新角色等
- [ ] **不要**做无凭证发 token 的 Cookie 版 `getSession`
- [ ] 对接时机：登录阶段之后、业务接口对接时

### 6. 其它收尾

- [ ] 验证码仍使用 `captchaId` Cookie（与会话 token 分离，需保留 `withCredentials`）
- [ ] `sys_perm` 菜单 URL/图标仍偏旧 Layui 路径，Soybean 路由对接时再映射
- [ ] App 线路 `/api/app/**` 登录与指纹（独立实现）

## 说明

「已落地」解决的是会话通道与过期策略；**不能**等同于 XSS/CSRF/劫持已完全消除。
残留面主要在：token 对 JS 可见（若继续 localStorage）、页面 XSS、HTTPS/运维配置、高危接口缺少二次认证。
