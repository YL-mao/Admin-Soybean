# 认证与会话安全：待办清单

> 范围：Soybean 管理端 + Sa-Token 严格 Header 模式。
> 更新：2026-09-03

## 已落地

- [x] `timeout` = 1 天（86400s）
- [x] `active-timeout` = 2 小时闲置冻结（7200s），`auto-renew` 开启
- [x] 关闭 Sa-Token Cookie 读/写（`is-read-cookie` / `is-lasting-cookie` = false），仅请求头 `saToken`
- [x] 移除 `getSession` 及 Cookie 会话恢复逻辑（不做无凭证发 token）
- [x] 登录账密通过后先 `logout` 再建会话（换新 token）
- [x] 「记住我」只本地记账号，不记密码；与 token 存活无关
- [x] Cookie 兜底属性：`httpOnly` + `sameSite=Lax`；生产 `secure=true`
- [x] 业务异常 / Sa-Token 内部异常不对前端暴露技术堆栈（系统繁忙文案）
- [x] 删除 Layui/Thymeleaf 页面入口与相关依赖（统一 JSON API）
- [x] Token 存 `localStorage`；管理端指纹：`X-Device-Id` + IP/UA，`/api/admin/**` 硬比对
- [x] 未登录对外统一文案；注销白名单 + 冻结态仍可注销；前端 401 清会话回登录

## 说明

- 已落地解决的是会话通道与过期策略。
- XSS 下 JS 可读存储仍可能被偷 token；当前以登录指纹限制换环境复用，不另立 XSS/CSP 专项待办。
- 经典 CSRF：自定义头 `saToken` + 鉴权不读 Cookie，面已收窄，暂不单独立项。
- 验证码仍用 `captchaId` Cookie（与会话 token 分离，需 `withCredentials`），属验证码实现细节。
- **菜单事实源已切到 `sys_menu` / `sys_menu_role`；`sys_perm` 已从种子与代码移除，禁止再用。**
- Soybean 动态路由 / 菜单管理页对接属业务阶段，不放本清单。
